## 1. Quantitative Performance on Held-Out Test Set

The model was evaluated strictly on the held-out test split ($N = 26$, ~17% of the total dataset), which was entirely isolated from both training and validation loops.

### Summary Metrics
| Metric | Value | Interpretation |
| :--- | :--- | :--- |
| **Test Loss** | **0.0000** | Cross-entropy indicating sharp, confident predictions |
| **Test Accuracy** | **100.0%** | All 26 test document layouts classified correctly |
| **Macro Precision** | **1.0000** | Zero false-positive predictions across all 5 classes |
| **Macro Recall** | **1.0000** | Zero false-negative predictions across all 5 classes |
| **Macro F1-Score** | **1.0000** | Perfect harmonic mean across classes |
| **Macro One-vs-Rest ROC AUC** | **1.0000** | Flawless separability at all threshold values |

> [!WARNING]
> **Methodological Reality Check:** Achieving 100% accuracy on 26 synthetic test images does **NOT** establish reliable performance on real-world document understanding. In the synthetic dataset generated by `training/generate_dataset.py`, each document category possesses prominent, noise-free visual invariants (e.g., barcodes on receipts, tabular grids on invoices, cursive signatures on letters). Real-world document classification (e.g., RVL-CDIP) must deal with heavy scanning noise, physical crumpling, faded thermal ink, multi-page variations, and hybrid layouts, where accuracy would be significantly lower without domain adaptation.

| **TFLite (FP32)** | 417.9 KB | **3.1x** | N/A* | N/A* | N/A* |
| **TFLite (INT8 Quantized)** | 111.6 KB | **11.4x** | N/A* | N/A* | N/A* |

*\* Runtime Environment Limitation Note:*
Model export, conversion, and quantization succeeded completely, reducing model size by up to 11.4x. However, in-process execution via `tf.lite.Interpreter` on this host environment encountered an upstream C-API wrapper ABI error (`AttributeError: _ARRAY_API not found` / `SystemError: CreateWrapperFromFile`). The installed Windows binary for TensorFlow 2.21 compiled its internal pybind11 TFLite wrapper against NumPy 1.x C-API, whereas the environment runs NumPy 2.4.6. As recommended by official TensorFlow guidance, running TFLite inference in production should either utilize NumPy < 2 or the modern `ai_edge_litert` runtime.
